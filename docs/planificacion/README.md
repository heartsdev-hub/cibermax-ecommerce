# Planificación del proyecto

#### 1. Nombre:

CiberMax eCommerce – Sistema Integral de Comercio Electrónico Multiplataforma con Chatbot.

#### 2. Descripción:

El proyecto consiste en desarrollar un sistema de comercio electrónico que permita a los clientes consultar productos, realizar compras y consultar el estado de sus pedidos a través de una plataforma digital.

Además, contará con un panel administrativo para gestionar productos, categorías, clientes, inventario, pedidos y pagos.

También se contempla la implementación de un chatbot que facilite la consulta de productos y pedidos, con la posibilidad de integrarse posteriormente con WhatsApp y Facebook.

#### 3. Planteamiento del problema:

Una empresa comercializa productos tecnológicos y gestiona sus ventas mediante conversaciones de WhatsApp y registros manuales.

Esta forma de trabajo puede generar dificultades para controlar el inventario, organizar los pedidos y brindar información actualizada a los clientes.

Asimismo, los compradores necesitan comunicarse directamente con el vendedor para consultar precios, disponibilidad y estado de sus pedidos.

Por ello, se plantea la necesidad de implementar una plataforma digital que centralice la información y facilite la gestión comercial.

#### 4. Justificación del problema:

El desarrollo del sistema ecommerce permitirá centralizar la administración de productos, clientes y pedidos en una única plataforma.

Se espera mejorar la organización de las ventas, facilitar el acceso a la información de los productos y reducir la dependencia de registros manuales.

Asimismo, el sistema permitirá ofrecer a los clientes una alternativa digital para realizar compras y consultar sus pedidos, mientras que los administradores dispondrán de herramientas para supervisar las operaciones comerciales.

#### 5. Objetivos del proyecto:

- Implementar un módulo de gestión de productos, categorías y subcategorías.
- Desarrollar un sistema de registro y autenticación de usuarios.
- Implementar un carrito de compras y registro de pedidos.
- Desarrollar un panel administrativo para gestionar inventario, ventas y clientes.
- Incorporar un chatbot para consultas de productos y pedidos.
- Realizar pruebas funcionales y de seguridad del sistema.

#### 6. Alcance del proyecto:

- Integración con WhatsApp Business API.
- Sistema avanzado de recomendaciones con inteligencia artificial.
- Integración con múltiples empresas de transporte.
- Operaciones de venta internacional.

#### 7. Identificación de usuarios y partes interesadas:

| Actor o interesado | Función |
| --- | --- |
| Cliente | Consultar productos, comprar y seguir pedidos. |
| Administrador | Gestionar usuarios, productos y ventas. |
| Personal de ventas | Atender pedidos y consultar pagos. |
| Personal de almacén | Gestionar existencias y preparación de pedidos. |
| Propietario del negocio | Revisar resultados y aprobar decisiones. |
| Equipo de desarrollo | Diseñar, programar y probar el sistema. |

#### 8. Estudio de viabilidad:

| Dimensión | Evaluación inicial |
| --- | --- |
| Técnica | Se propone desarrollar el backend con Java y Spring Boot, una base de datos relacional y clientes web y móvil conectados a servicios compartidos. Se validará la experiencia del equipo y la compatibilidad entre componentes. |
| Económica | Se evaluarán los costos de desarrollo, dominio, alojamiento, infraestructura, herramientas, servicios externos y soporte. La viabilidad financiera dependerá del presupuesto aprobado. |
| Operativa | Los clientes podrán comprar desde la web o la app; los trabajadores autorizados gestionarán productos, existencias, pedidos y pagos desde el panel administrativo. |
| Temporal | Se priorizará una primera versión operativa y se comprobará el plazo real según la cantidad de desarrolladores disponibles. |
| Legal | Se revisarán las obligaciones peruanas aplicables a protección de datos personales, atención al consumidor, comprobantes y procesamiento de pagos. |

**Conclusión preliminar:** el proyecto es técnicamente factible con tecnologías disponibles, sujeto a validar recursos humanos, presupuesto, plazo, integraciones y requisitos legales.

#### 9. Recursos necesarios:

| Tipo | Recursos propuestos |
| --- | --- |
| Humanos | Responsable del proyecto, analista, diseñador UI/UX, desarrolladores backend, web y móvil, responsable de pruebas y apoyo de infraestructura. Una persona puede cubrir varios roles. |
| Software | Java, Spring Boot, entorno de desarrollo, Git y GitHub, Figma, Draw.io, Postman y herramientas de pruebas. |
| Base de datos | PostgreSQL o MySQL, a seleccionar según requerimientos y compatibilidad. |
| Infraestructura | Computadoras, internet, servidor de desarrollo, servidor de producción, dominio, certificado HTTPS y sistema de copias de seguridad. |
| Integraciones | Pasarela de pagos o validación de pagos, mensajería, notificaciones y futuras conexiones con WhatsApp y Facebook, según alcance aprobado. |

#### 10. Metodología de trabajo:

Se propone trabajar con **Scrum**, organizando las funcionalidades del ecommerce, panel administrativo, aplicación móvil y chatbot en un Product Backlog priorizado. El proyecto se ejecutará en sprints de dos semanas, con planificación al inicio, seguimiento de avances, revisión del incremento y retrospectiva al cierre.

La primera prioridad será habilitar el catálogo, usuarios, carrito y pedidos; posteriormente se integrarán administración, pagos, app móvil y chatbot, según dependencias y capacidad del equipo. Cada funcionalidad deberá cumplir criterios de aceptación y pruebas antes de considerarse terminada.

#### 11. Cronograma del proyecto:

**Propuesta referencial de 20 semanas, pendiente de validación con el equipo:**

| Actividad | Periodo estimado |
| --- | --- |
| Planificación y definición del alcance | Semanas 1–2 |
| Análisis de requisitos e historias de usuario | Semanas 3–4 |
| Diseño de interfaces, arquitectura y base de datos | Semanas 5–6 |
| Desarrollo del backend, ecommerce web y panel administrativo | Semanas 7–12 |
| Desarrollo e integración de la aplicación móvil | Semanas 11–15 |
| Desarrollo e integración del chatbot | Semanas 13–16 |
| Pruebas integrales, seguridad y correcciones | Semanas 15–19 |
| Despliegue inicial, documentación y validación | Semana 20 |

Las pruebas unitarias y de integración se efectuarán también durante el desarrollo, sin esperar a las semanas finales.

#### 12. Presupuesto del proyecto:

El presupuesto se elaborará en soles (S/) a partir de cotizaciones y horas reales estimadas. Se contemplarán los siguientes conceptos:

| Concepto | Criterio de estimación |
| --- | --- |
| Personal de desarrollo y diseño | Horas por rol × tarifa acordada. |
| Dominio y hosting | Tarifas del proveedor y periodo contratado. |
| Base de datos, almacenamiento y respaldos | Plan elegido y consumo proyectado. |
| Servicios de pago y mensajería | Tarifas por transacción, mensaje o consumo. |
| Equipos y herramientas | Compras o suscripciones necesarias. |
| Pruebas y publicación | Costos de ambientes, dispositivos y distribución de la app. |
| Mantenimiento | Horas de soporte y costos periódicos. |
| Contingencia | Reserva aprobada para imprevistos. |

**Presupuesto total:** pendiente de cálculo y aprobación. No se asignan montos sin cotizaciones ni estimación del esfuerzo.

#### 13. Identificación y gestión de riesgos:

| Riesgo | Nivel preliminar | Medida de respuesta |
| --- | --- | --- |
| Retrasos por complejidad de la web, app y chatbot | Alto | Priorizar un producto mínimo viable, definir hitos y revisar avances por sprint. |
| Cambios frecuentes en funcionalidades | Alto | Mantener un backlog priorizado y evaluar impacto de nuevos requisitos. |
| Errores en pedidos, pagos o inventario | Alto | Aplicar validaciones, pruebas automatizadas y controles de consistencia. |
| Acceso no autorizado o pérdida de datos | Alto | Implementar permisos por rol, HTTPS, respaldos y pruebas de seguridad. |
| Problemas de conexión con APIs externas | Medio/alto | Probar integraciones temprano y disponer de manejo de fallos. |
| Sobrecostos de infraestructura y servicios | Medio | Supervisar consumo, cotizar servicios y definir límites presupuestarios. |
| Dificultades de uso por parte del personal | Medio | Validar prototipos y elaborar capacitación y manuales. |

La probabilidad, el impacto y los responsables se ajustarán durante el análisis del proyecto.

#### 14. Entregables del proyecto:

- Plan del proyecto, alcance, cronograma, presupuesto y matriz de riesgos.
- Documento de requisitos funcionales y no funcionales, épicas e historias de usuario.
- Prototipos de la web, aplicación móvil y panel administrativo.
- Diagramas de arquitectura, procesos y modelo de base de datos.
- Código fuente versionado del backend, ecommerce web, panel administrativo, app móvil y chatbot.
- Base de datos e integraciones necesarias para las funciones aprobadas.
- Casos de prueba, evidencias y registro de correcciones.
- Primera versión operativa desplegada y validada.
- Manual de usuario, guía del administrador y documentación técnica.

#### 15. Criterios de éxito del proyecto:

- Los clientes pueden consultar productos, registrarse o iniciar sesión y realizar pedidos mediante el ecommerce.
- La aplicación móvil permite ejecutar las funcionalidades de compra definidas para su primera versión.
- El panel administrativo permite gestionar productos, categorías, inventario, clientes, pedidos y registros de pago según los permisos asignados.
- El chatbot responde correctamente a las consultas de productos y estados de pedidos incluidas en el alcance aprobado.
- Los pedidos realizados desde los canales disponibles se registran de forma consistente y pueden consultarse desde el panel administrativo.
- Se aprueban el 100 % de los casos de prueba críticos establecidos antes del lanzamiento, sin defectos críticos abiertos.
- Se verifican los controles básicos de autenticación, autorización, protección de datos y copias de seguridad.
- Los representantes designados de Ciber Max validan el cumplimiento de los criterios de aceptación antes de la entrega de la primera versión.
